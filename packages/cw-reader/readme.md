# cw-reader

ComfyUI Workflow Reader

```
npm install @stable-canvas/cw-reader
```

references:

- [comfyui-client](https://github.com/StableCanvas/comfyui-client)

# Usage

- NodeJS

```ts
import { ImageReader } from "@stable-canvas/cw-reader";
const file1 = await fs.promises.readFile("./tests/img2img_workflow.png");
const reader = new ImageReader(file1.buffer);
const workflow = await reader.getWorkflowJson();
await fs.promises.writeFile(
  "./img2img_workflow.json",
  JSON.stringify(workflow, null, 2),
);
```

- ESM

```html
<input type="file" accept="image/*" />
<pre><code id="output">// Output will appear here</code></pre>

<script type="module">
  import { ImageReader } from "https://esm.run/@stable-canvas/cw-reader";

  const fileInput = dropZone.querySelector("input");
  const output = document.getElementById("output");

  async function handleFile(file) {
    try {
      const arrayBuffer = await file.arrayBuffer();
      const reader = new ImageReader(arrayBuffer);
      const workflow = await reader.getWorkflowJson();
      output.textContent = JSON.stringify(workflow, null, 2);
    } catch (err) {
      output.textContent = `Error: ${err.message}`;
    }
  }
</script>
```

# Workflow Support

`JsonReader` supports ComfyUI workflow JSON versions `0.4` and `1`. Version 1 object links and object-form `widgets_values` are normalized to the internal API prompt format.

UI-exported workflows are converted with executable-node semantics:

- `Note`, `MarkdownNote`, and `Reroute` nodes are normalized or removed.
- `PrimitiveNode` values are inlined into their consumers.
- Bypassed nodes (`mode: 4`) rewire compatible inputs to outputs.
- Muted terminal nodes (`mode: 2`) are removed. A live node that still depends on a muted node raises an error.
- `extra.groupNodes` definitions are expanded into their executable nodes.

Widget names use the explicit mapping table plus the bundled node schema. Unknown non-empty widgets are rejected instead of being emitted under an approximate name. API-format export remains the most reliable input when a workflow uses unsupported custom nodes.

# What is `./data/\*.json`

## `comfyui.node.types.json`

This file comes from the ComfyUI runtime and is used during code generation to annotate output types.

(The “types” here refer to internal types used by ComfyUI; in the generated code, they are only written as comments without any type checking.)

It is generated by a script. Since the script is extremely simple, it doesn’t make sense to open source it for now. Also, whether this file is correct or not does not affect the use of the library, so it won’t be updated in real-time.

## `comfyui.node.widgets.json`

This file provides the base widget-name mapping for non-API workflows. Current core-node corrections are defined in `JsonReader`, and the bundled node schema is used as a fallback for newer nodes.

Workflow definition files omit some information needed for API requests. If both the mapping and schema are insufficient for a non-empty widget, parsing fails rather than emitting an approximate input name.

Therefore, it is not recommended to use workflow documents for code generation.
